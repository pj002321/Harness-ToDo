# 설계 근거

## 하네스란

모델 바깥에서 모델의 일을 **구조로 통제하는 코드**. 프롬프트가 "부탁"이라면 하네스는 "환경"이다.
이 저장소에서 하네스가 쥐고 있는 것은 네 가지다.

| 하네스가 쥔 것 | 어디서 | 모델에게 맡기면 생기는 일 |
|---|---|---|
| **순서** — 누가 언제 일하나 | `harness/run.js` | 아무 기사나 대충 골라 요약 |
| **권한** — 누가 무엇을 할 수 있나 | `claude -p --tools ''` | 기사 속 숨은 지시(인젝션)가 실행됨 |
| **출력 모양** — 무엇을 넘겨주나 | `--json-schema` | 파싱 실패, 애매한 "대체로 맞음" |
| **판정** — 언제 통과인가 | `check()`의 pass 계산, `grounded()`, `MAX_ATTEMPTS` | 근거 없는 문장이 그대로 발행 |

## 원문 구조와 이 저장소의 대응

원문(Anthropic, 2026-03)은 생성자/판별자를 분리한 GAN에서 착안해 세 에이전트를 썼다.

| 원문 | 여기 | 하는 일 |
|---|---|---|
| Planner | **Editor** | 분야마다 후보(최대 12개) 중 중요한 기사 선정·중복 제거, 기사마다 계약(브리프) |
| Generator | **Writer** | 계약대로 3문장 이내 요약. FAIL 판정을 받으면 고쳐 씀 |
| Evaluator | **Checker** | 문장마다 원문 근거 구절을 인용. 원문에서 가장 튜닝이 어려웠던 부품 |
| Sprint Contract | **브리프** | 쓰기 전에 "이 요약이 해내야 할 것"을 정함. Checker의 채점표 |
| Playwright로 앱 조작 | **원문 대조** | 판정 대상이 앱이 아니라 문장이므로 |

원문은 앱 개발에 이 구조를 썼다. 여기선 **매일 반복되는 콘텐츠 자동화**에 쓴다 —
사람이 매번 검토할 수 없으니, AI 결과물이 사고를 치지 않게 막는 장치가 더 중요해지는 영역이다.

## 결정과 이유

**수집과 분야 분류는 코드가 한다 (`collect.js`).** 언론사 RSS가 이미 분야별로 나뉘어 있으니, 기사의 분야를 모델에게 묻지 않는다.
본문이 500자 미만인 기사는 근거 검증이 불가능하므로 후보에서 아예 뺀다. 같은 기사가 여러 피드에 있으면 한 분야에만 둔다.

**하네스는 하루 1회, 개인화는 코드로.** 독자마다 하네스를 돌리면 비용이 방문자 수에 비례하고, 방문자가 AI 호출을 유발할 수 있다(남용).
모든 독자가 보는 후보는 같으므로 요약·검증은 하루 한 번 하고, 독자의 분야 선택은 서버가 `digest.json`을 필터링해서 처리한다.
선택은 GET 폼 + 쿠키로 기억 — 로그인도 스크립트도 필요 없다.

**API 키 vs 구독.** 로컬 실행은 각자의 Claude Code 로그인(구독 가능)으로 돈다. 공개 사이트로 운영할 땐 서버에서 운영자 API 키로 하루 1회 돌린다.
구독 계정으로 남을 대신해 AI를 돌려주는 형태는 피한다.

**모든 에이전트에 도구 0개.** 기사 원문은 신뢰할 수 없는 입력이다. 원문에 "이전 지시를 무시하고…"가 숨어 있어도
에이전트에겐 실행할 손이 없다. 필요한 자료는 하네스가 `<article>` 태그로 감싸 프롬프트에 넣는다.

**인용은 코드가 재대조한다 (`grounded()`).** Checker가 `supported: true`라고 해도, 그 `quote`가 원문에
글자 그대로(공백·따옴표·대소문자 차이만 허용, 15자 이상) 없으면 FAIL. 첫 실행에서 Checker가 원문을 "요약해서 인용"한 2건이 여기서 걸렸다.
한계: 인용은 맞는데 **번역·단위 변환이 틀린 경우**(49 billion → 49억)는 코드로 못 잡는다. 이건 Checker 프롬프트의 몫이다.

**합격은 하네스가 계산한다.** 모든 문장에 판정이 있고, supported이고, 인용이 실재하고, 계약 미충족(unmet)이 없어야 PASS.

**매 호출이 새 세션.** 맥락(원문, 브리프, 직전 판정)은 하네스가 매번 넣어준다 — 원문의 context reset + 구조화된 인계.

**개인 설정 격리 (`--setting-sources ''`, `--strict-mcp-config`).** 실행하는 사람의 CLAUDE.md·훅·MCP가 섞이면 결과가 사람마다 달라진다.

**solo와 harness를 같은 감사로 비교 (`AUDIT=1`).** 발행 전에 둘 다 계약 없이 "근거 없는 문장 수"만 세는 독립 검수를 받는다.
같은 날은 같은 기사 스냅샷을 쓰므로 입력도 같다. 매일 운영할 땐 끈다(기사 수만큼 호출이 는다).

**브리핑 HTML은 escape + CSP.** 기사 제목·URL은 외부 입력이다. 모든 값을 escape하고, `http(s)` 외의 URL은 버리고,
페이지 자체에 스크립트 금지 CSP를 건다.

**저작권: 요약 3문장 상한, 본문 비공개.** 문장 수는 `--json-schema`의 `maxItems`로 요구하고 발행 때 한 번 더 자른다.
`digest.json`에는 본문(`text`)을 넣지 않고, `sources/`(원문 스냅샷)는 커밋하지 않는다. 썸네일은 저장하지 않고 원문 이미지 주소를 쓴다.

## 일부러 뺀 것 (그리고 언제 넣을지)

- **차단된 소스** — 매일경제(403), GeekNews(403) 등. 차단을 우회하지 않는다. 동아일보는 본문 대신 메뉴 문구가 추출되어 뺐다.
- **언론사별 본문 정리** — 정규식 `<p>` 추출에 송고 시각·공유 버튼 문구가 섞인다. 요약 품질을 해치면 출처별 규칙 추가.
- **메일·슬랙 전송** — 지금은 사이트로 충분. 받아보는 곳이 정해지면 `finish()` 뒤에 추가.
- **중복 기사 병합, 기사 간 교차 검증** — 하루 몇 건 규모에선 Editor 판단으로 충분.

## 원문의 마지막 교훈

> 하네스의 모든 부품은 "모델이 혼자서는 못 하는 것"에 대한 가정이다. 모델이 좋아지면 그 가정은 낡는다.

그래서 부품을 하나씩 빼보며 실제로 하중을 받는지(load-bearing) 확인해야 한다. 이 저장소에서 해볼 수 있는 실험:
`grounded()` 재대조 끄기, `MAX_ATTEMPTS = 1`, 계약 없이 쓰기, 더 강한/약한 모델 — 각각 `AUDIT=1`로 돌려 과정 페이지의 `근거 없는 문장` 수가 어떻게 바뀌는지 본다.
